Latency spike (100ms → 3s)

  • DB lock contention / slow query
  • GC pressure (heap tăng)
  • Connection pool exhaustion
  • Downstream degradation
  • DNS timeout

Memory leak (OOM sau 12h)

  • Goroutine leak (channel/context)
  • Unbounded cache
  • Unclosed response body
  • time.Ticker không Stop
  • Slice giữ ref array lớn

Ví dụ áp dụng: "escape analysis là gì?"

What: compiler quyết định stack/heap tại compile-time. How: phân tích địa chỉ biến có thoát scope hàm không. Why: stack rẻ (không GC). Trade-off: pointer cho struct lớn buộc heap nhưng tránh copy. When: check -gcflags="-m", chỉ tối ưu hot path.

? Rapid-fire Q&A

Trả lời trong 30 giây, không notes.

QGiải thích slice internals trong 30 giây.+

Struct 3 field: ptr, len, cap. Append trong cap ghi tại chỗ; hết cap thì cấp array mới (double <256, +25% lớn hơn). Sub-slice chia sẻ backing → aliasing trap; dùng a[l:h:h] để chặn.

QGMP trong một câu.+

G (goroutine) chạy trên M (OS thread) được điều phối bởi P (logical CPU = GOMAXPROCS); mỗi P có local run queue, work stealing cân bằng tải, syscall block thì P nhảy sang M khác.

QNil interface trap.+

Interface = (type, data), chỉ nil khi cả hai nil. Trả *MyError nil qua error → type non-nil → interface KHÁC nil. Fix: return nil trực tiếp.

QVì sao STW của Go ngắn?+

Marking concurrent (chạy cùng chương trình), STW chỉ ở mark setup + termination (~10-100µs). Write barrier đảm bảo đúng đắn khi mark song song. Từ 1.14 preemption bất đồng bộ giúp STW ổn định sub-ms.

QCấu hình HTTP client production?+

Client.Timeout tổng + Transport (MaxIdleConnsPerHost, MaxConnsPerHost, IdleConnTimeout, TLSHandshakeTimeout). LUÔN defer resp.Body.Close() + đọc hết body để tái dùng connection. Không dùng DefaultClient.

QCAP một câu.+

Khi network partition (bắt buộc trong hệ phân tán), chọn CP (từ chối để giữ nhất quán) hay AP (trả data cũ để giữ khả dụng). CA chỉ có ở hệ một node.

QChống double charge?+

Idempotency key: check store → completed trả cached, chưa có thì lock + xử lý + lưu. Consumer idempotent: lưu message ID trong cùng transaction với business logic, skip trùng.

QCircuit breaker 3 trạng thái?+

Closed (đếm lỗi, vượt ngưỡng → Open) → Open (fail nhanh, sau timeout → Half-Open) → Half-Open (thử 1 request: OK → Closed, lỗi → Open). Chặn cascading failure.

QDebug latency spike production?+

Metrics (khi nào, đột ngột/dần) → correlate deploy/traffic → tracing khoanh service → profile (CPU/mem/lock) → DB (pool, slow query, lock) → network. Root cause → fix → verify → post-mortem.

QSenior khác mid-level?+

Scope rộng hơn ticket, giải thích trade-off, thiết kế cho failure, communication đa đối tượng, ownership (dẫn dắt + post-mortem), pragmatism (ship giải pháp hoạt động). Không chỉ "biết đáp án".

QKhung trả lời câu hỏi kỹ thuật?+

What → How → Why → Trade-offs → When to use/not use. Với problem solving: Understand → Scope → Options → Trade-offs → Decision.

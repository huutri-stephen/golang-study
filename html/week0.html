i Overview & TL;DR

Bộ plan gốc rất mạnh về internals/concurrency/distributed nhưng nhẹ phần "chững tay hằng ngày". Đây là những thứ ít được ôn nhưng hay lộ ra ngay ở coding round hoặc câu hỏi phụ.

TL;DR

1 Modules & Dependency Management

FileVai trò
go.modtên module + Go version + dependency (trực tiếp & indirect)
go.sumchecksum (hash) từng version → chống ai đó sửa version đã publish (supply-chain)
MVS — Minimal Version Selection

Go chọn version thấp nhất thỏa mãn mọi yêu cầu (npm chọn cao nhất). Kết quả: build reproducible, không "tự vỡ" khi có minor version mới. go.sum đảm bảo nội dung version không đổi.

Semantic Import Versioning

Major ≥ 2 phải đổi import path: github.com/x/y/v2. Nhờ vậy v1 và v2 cùng tồn tại trong một build. Major = breaking change.

LệnhÝ nghĩa

go get pkg@v1.2.3thêm/nâng version cụ thể
go mod vendorcopy dep vào vendor/ (build offline/audit)
go work use ./mworkspace cho monorepo (thay replace)

2 Testing chiều sâu

Table-driven + subtests (idiom chuẩn)
tests := []struct{ name string; in, want int }{
    {"gold", 100, 80},
    {"silver", 100, 90},
}
for _, tt := range tests {
    t.Run(tt.name, func(t *testing.T) {  // subtest: chạy/lọc riêng
        if got := Discount(tt.in); got != tt.want {
            t.Errorf("got %d want %d", got, tt.want)
        }
    })
}

Thêm case = thêm 1 dòng. t.Run báo cáo rõ case nào fail và lọc được -run TestX/gold.

Mock qua interface (không có mock magic)

Định nghĩa interface nhỏ ở phía consumer, viết implementation giả cho test. Lib hỗ trợ: gomock (sinh code), testify/mock, moq. Interface ở consumer → dễ mock, giảm coupling.

Coverage

go test -coverprofile=c.out ./...
go tool cover -html=c.out

Coverage cao ≠ test tốt. Ưu tiên branch quan trọng + edge case.

Fuzzing (1.18+)

func FuzzParse(f *testing.F) {
  f.Add("seed")
  f.Fuzz(func(t *T, s string){...})
}

Tự sinh input tìm crash/sai. Kiểm tra property (round-trip).

assert vs require · Helper · Cleanup
  • assert ghi lỗi rồi tiếp tục; require ghi lỗi và dừng ngay (dùng cho precondition).
  • t.Helper() → stacktrace trỏ về dòng gọi thật, không phải trong helper.
  • t.Cleanup(fn) → dọn dẹp sau test (đúng cả với subtest & parallel).

4 Error Handling hiện đại

return fmt.Errorf("load user %s: %w", id, err)  // %w giữ chain, unwrap được

errors.Is — theo GIÁ TRỊ

if errors.Is(err, sql.ErrNoRows) {
    return ErrNotFound
}

"Có phải lỗi X không?" — dùng cho sentinel error.

errors.As — theo KIỂU

var pg *pgconn.PgError
if errors.As(err, &pg) {
    _ = pg.Code // đọc field
}

Trích custom error type để đọc metadata bên trong.

Nguyên tắc senior
  • Xử lý lỗi một lần: hoặc log, hoặc return — không cả hai (tránh log trùng).
  • Layer dưới wrap + return kèm context; layer ngoài cùng log một lần.
  • panic chỉ cho lỗi lập trình không hồi phục, KHÔNG cho lỗi nghiệp vụ.

5 encoding/json (thực chiến)

type User struct {
    ID       string `json:"id"`
    Password string `json:"-"`                 // KHÔNG bao giờ serialize
    Nickname string `json:"nickname,omitempty"` // bỏ khi zero value
}
Bẫy hay gặp
  • Field không exported (chữ thường) → json bỏ qua. Phải viết hoa.
  • Số JSON vào interface{} → luôn thành float64 (mất chính xác int64 lớn). Dùng json.Number / UseNumber().
  • omitempty không áp dụng cho struct lồng non-pointer → dùng con trỏ.
Streaming + strict
dec := json.NewDecoder(r.Body)
dec.DisallowUnknownFields()  // reject field lạ (strict API)
dec.Decode(&u)                // stream, không load hết vào RAM

6 Reflection & Ecosystem

json.Marshal hoạt động thế nào?

Dùng reflection (reflect) duyệt field exported, đọc struct tag json:"..." để lấy key + option, rồi encode đệ quy. Vì reflection nên chậm hơn code sinh sẵn và cần field exported. Đây cũng là nền của ORM (GORM) và validator.

Nhược điểm reflection

Chậm (nhiều lần code tĩnh), mất type-safety (lỗi runtime thay vì compile-time), khó đọc. Chỉ dùng cho serialization/framework, tránh hot path.

Config

Ưu tiên: flag > env > file > default. 12-factor: config/secret qua env, không hardcode/commit.

Logging

log/slog (stdlib 1.21+) structured. Hoặc zap/zerolog. JSON/key-value dễ query trên ELK/Loki.

? Flashcards

Qgo.mod vs go.sum?+

go.mod khai báo module + Go version + dependency. go.sum chứa checksum từng version để đảm bảo toàn vẹn, chống ai đó sửa version đã publish (supply-chain security).

QMVS là gì, khác npm thế nào?+

Minimal Version Selection — Go chọn version thấp nhất thỏa mãn mọi yêu cầu; npm chọn cao nhất. MVS làm build reproducible, ổn định.

QVì sao major ≥ 2 phải đổi import path?+

Semantic Import Versioning: github.com/x/y/v2. Major = breaking change; đổi path cho phép v1 và v2 cùng tồn tại trong một build.

QMock trong Go làm thế nào?+

Định nghĩa interface nhỏ ở phía consumer, viết implementation giả cho test. Dùng gomock/testify/moq. Interface ở consumer → dễ mock, giảm coupling.

Qassert vs require (testify)?+

assert ghi lỗi nhưng test tiếp tục; require ghi lỗi và dừng ngay — dùng cho precondition (nếu setup fail thì các assert sau vô nghĩa).

QFuzzing giải quyết gì?+

Tự sinh input ngẫu nhiên từ seed corpus để tìm case gây panic/sai mà con người khó nghĩ ra — đặc biệt cho parser/encoder. Kiểm tra property như round-trip.

Qgo vet vs golangci-lint?+

go vet là công cụ stdlib phát hiện bug tĩnh cơ bản. golangci-lint là meta-linter chạy hàng chục linter (govet, staticcheck, errcheck, gosec...) song song — chuẩn CI.

Q%w khác %v? errors.Is vs errors.As?+

%w bọc error giữ chain (unwrap được); %v chỉ nối chuỗi. errors.Is so khớp theo giá trị (sentinel); errors.As trích theo kiểu (custom struct) để đọc field.

QVì sao field struct không ra JSON?+

Field không exported (chữ thường) → json dùng reflection chỉ thấy exported field. Phải viết hoa chữ đầu.

QUnmarshal số vào interface{} bị gì?+

Luôn thành float64 → mất chính xác với int64 lớn. Dùng json.Number qua UseNumber() hoặc unmarshal vào kiểu cụ thể.

Qjson.Marshal hoạt động thế nào bên dưới?+

Dùng reflection duyệt field exported, đọc struct tag json để lấy key + option (omitempty, -), encode đệ quy. Vì reflection nên chậm và cần field exported.

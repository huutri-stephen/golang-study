3 Bean scope & circular dependency

Scope

singleton (mặc định): một instance toàn container → phải stateless/thread-safe. prototype: mỗi lần lấy tạo mới. Web: request, session, application.

Circular dependency

Constructor injection cả hai chiều → Spring không giải được → BeanCurrentlyInCreationException lúc khởi động (fail fast — tốt). Field/setter singleton → giải được nhờ early reference (tiêm instance chưa init xong) → che giấu vấn đề thiết kế. Xử lý đúng: thiết kế lại, hoặc @Lazy/ObjectProvider.

4 Spring AOP & proxy

Proxy-based AOP

Spring AOP dùng runtime proxy (không weaving bytecode như AspectJ). Bean có aspect (@Transactional, @Async, @Cacheable) → container thay bean thật bằng proxy bọc ngoài, chèn advice trước/sau method.

@Service class UserService {
    public void outer() { inner(); }           // this.inner() -> KHÔNG qua proxy
    @Transactional public void inner() {...}  // annotation bị bỏ qua!
}

Proxy chỉ chặn lời gọi từ ngoài vào. this.inner() gọi thẳng object thật → không mở transaction. Fix: tách bean khác, self-inject, hoặc AopContext.currentProxy().

5 @Transactional internals

Cơ chế

Advice TransactionInterceptor (qua proxy) bọc method: mở transaction (hoặc join) trước, commit nếu thành công, rollback nếu ném exception.

Rollback rule + 4 bẫy
  • Mặc định rollback với RuntimeException + Error; KHÔNG rollback checked exception (cần rollbackFor).
  • Self-invocation (mục 4).
  • Method private/non-public → proxy không chặn → vô hiệu.
  • Nuốt exception bên trong → transaction không thấy lỗi → không rollback.
Propagation

REQUIRED (mặc định): join hoặc tạo mới. REQUIRES_NEW: suspend transaction ngoài, tạo mới độc lập (audit log). NESTED: savepoint. SUPPORTS/MANDATORY/NEVER...

6 Spring Boot auto-configuration

Cơ chế

@SpringBootApplication = @Configuration + @ComponentScan + @EnableAutoConfiguration. @EnableAutoConfiguration nạp danh sách auto-config class từ AutoConfiguration.imports (Boot 2.7+). Mỗi class dùng @Conditional:

  • @ConditionalOnClass — có class X trên classpath (vd DataSource → cấu hình JDBC).
  • @ConditionalOnMissingBean — chỉ tạo nếu user chưa định nghĩa → cho phép override.
  • @ConditionalOnProperty — bật theo config.
Override auto-configured bean

Định nghĩa bean cùng kiểu; @ConditionalOnMissingBean khiến auto-config nhường. Starter chỉ là gói dependency → classpath có gì thì auto-config kích hoạt cái đó.

7 REST & exception handling

@RestController @RequestMapping("/api/users")
class UserController {
    @GetMapping("/{id}") UserDto get(@PathVariable long id) {...}
    @PostMapping @ResponseStatus(HttpStatus.CREATED)
    UserDto create(@RequestBody @Valid CreateUserRequest req) {...}
}
@RestControllerAdvice
class ApiExceptionHandler {
    @ExceptionHandler(NotFoundException.class) @ResponseStatus(HttpStatus.NOT_FOUND)
    ErrorResponse handle(NotFoundException e) {...}
}

@RestController = @Controller + @ResponseBody (JSON qua Jackson). @RestControllerAdvice gom xử lý exception tập trung. @Valid + Bean Validation. Không trả entity Hibernate trực tiếp → dùng DTO.

8 System design

Làm rõ yêu cầu
QPS, data size, đọc/ghi, ràng buộc.
API + data model
REST/gRPC, resource, schema.
High-level architecture
service, DB, cache, queue.
Đi sâu bottleneck
DB (replica/shard), cache, message queue.
Trade-off
consistency vs availability, sync vs async.
Microservices resilience

Circuit breaker (Resilience4j): sau ngưỡng lỗi "mở" → fail nhanh, thử lại sau (half-open) → tránh cascade failure. Retry + timeout + bulkhead. API gateway. REST/gRPC (sync) vs Kafka/RabbitMQ (async, decoupling, eventual consistency).

Scalability & idempotency

Service stateless → scale ngang sau load balancer; state đẩy ra Redis/DB. Idempotency key cho POST (payment): lưu key + kết quả, nhận lại key đã xử lý → trả kết quả cũ → an toàn khi retry (tránh double charge). Observability: metrics (Micrometer/Prometheus), tracing (OpenTelemetry), health check.

? Flashcards

QBean lifecycle của Spring theo thứ tự nào?+

Instantiate (constructor) → populate properties (DI) → Aware callbacks → BeanPostProcessor.before → @PostConstruct/afterPropertiesSet → BeanPostProcessor.after (AOP PROXY tạo ở đây) → sẵn sàng → @PreDestroy/destroy khi context đóng.

QProxy AOP được tạo ở bước nào? Hệ quả?+

Ở postProcessAfterInitialization (BeanPostProcessor). Hệ quả: self-invocation (this.method()) bỏ qua proxy vì gọi thẳng object thật → @Transactional/@Async trong cùng bean không hoạt động.

QBeanPostProcessor là gì?+

Hook mở rộng mạnh nhất của Spring: chạy before/after mỗi bean init. AOP proxy, @Autowired resolution đều là BeanPostProcessor. Cho phép sửa/bọc bean trước khi dùng.

QVì sao constructor injection tốt hơn field injection?+

Cho phép field final (bất biến), dependency rõ ràng và bắt buộc (compiler ép), dễ test đơn vị (new + mock, không cần Spring/reflection), và phát hiện circular dependency sớm lúc khởi động.

QCircular dependency: constructor vs field injection?+

Constructor injection cả hai chiều → Spring không giải được → BeanCurrentlyInCreationException (fail fast, tốt). Field/setter singleton → giải được nhờ early reference (tiêm instance chưa init xong) → che giấu vấn đề thiết kế.

QBean scope mặc định? Điều kiện?+

Singleton — một instance trên toàn container, chia sẻ cho mọi nơi. Vì thế bean singleton PHẢI stateless/thread-safe. Scope khác: prototype (mỗi lần lấy tạo mới), request, session.

QJDK dynamic proxy vs CGLIB?+

JDK proxy implement interface (Proxy class). CGLIB sinh subclass của class (không cần interface, nhưng không proxy được final/private). Spring Boot mặc định CGLIB (proxyTargetClass=true).

QVì sao @Transactional self-invocation không hoạt động?+

Spring AOP dùng proxy bọc ngoài; proxy chỉ chặn lời gọi TỪ NGOÀI. Gọi this.method() trong cùng bean đi thẳng object thật, bỏ qua proxy → advice (transaction) không chạy. Fix: tách bean khác hoặc self-inject.

Q@Transactional trên private method có tác dụng không?+

Không. Proxy (JDK interface hoặc CGLIB subclass) chỉ chặn được public method gọi từ ngoài. private/final/non-public method không bị proxy chặn → annotation vô hiệu.

Q@Transactional rollback khi nào?+

Mặc định rollback với RuntimeException và Error; commit khi thành công. Checked exception KHÔNG rollback (cần rollbackFor). Bẫy: nuốt exception bên trong → transaction không thấy lỗi → commit.

QREQUIRED vs REQUIRES_NEW?+

REQUIRED (mặc định): join transaction hiện có hoặc tạo mới. REQUIRES_NEW: suspend transaction ngoài, tạo transaction mới độc lập → commit dù transaction ngoài rollback (dùng cho audit log).

QSpring Boot auto-configuration hoạt động thế nào?+

@EnableAutoConfiguration nạp danh sách config class (từ AutoConfiguration.imports). Mỗi class dùng @Conditional: @ConditionalOnClass (có class trên classpath), @ConditionalOnMissingBean (chỉ tạo nếu user chưa định nghĩa), @ConditionalOnProperty. Classpath có gì thì kích hoạt cái đó.

QLàm sao override một auto-configured bean?+

Định nghĩa bean cùng kiểu trong config của bạn. Auto-config dùng @ConditionalOnMissingBean nên sẽ nhường (không tạo bean mặc định nữa).

Q@SpringBootApplication gồm gì?+

@Configuration + @ComponentScan + @EnableAutoConfiguration. Quét component trong package, bật auto-config, và bản thân là config class.

QCircuit breaker giải quyết gì?+

Khi downstream lỗi liên tục, breaker "mở" → fail nhanh không chờ timeout, thử lại sau (half-open). Tránh cascade failure và cạn tài nguyên (thread/connection chờ service chết). Dùng Resilience4j.

QĐồng bộ (REST/gRPC) vs bất đồng bộ (queue) khi nào?+

REST/gRPC khi cần phản hồi ngay, coupling chấp nhận được. Queue (Kafka/RabbitMQ) khi cần decoupling, chịu tải đỉnh (buffer), fan-out sự kiện, xử lý async — đổi lại phức tạp hơn và eventual consistency.

QLàm service scale ngang thế nào?+

Giữ stateless (đẩy state ra Redis/DB, không session cục bộ), đặt sau load balancer, DB read replica/sharding + pool đúng size, tác vụ nặng đẩy queue xử lý async, observability đầy đủ.

QIdempotency key dùng để làm gì?+

Client gửi key duy nhất cho mỗi thao tác (vd payment). Server lưu key + kết quả; nếu nhận lại key đã xử lý → trả kết quả cũ thay vì thực thi lại → an toàn khi client retry (tránh double charge).

QCấu trúc trả lời một bài system design?+

Làm rõ yêu cầu & scale (QPS, data size) → định nghĩa API → data model → high-level architecture → đi sâu bottleneck (DB/cache/queue) → bàn trade-off. Không nhảy vào chi tiết trước khi chốt phạm vi.

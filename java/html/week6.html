Modern Java & IO/NIO

Record biên dịch thành gì, sealed enforce compile + runtime, switch desugar, và NIO buffer/channel/selector khác IO blocking chỗ nào.

i Overview & TL;DR

TL;DR
  • Record: equals/hashCode qua invokedynamic + ObjectMethods.bootstrap; immutable KHÔNG sâu nếu component mutable.
  • Sealed enforce compile + class file attribute PermittedSubclasses; ADT sum + product.
  • instanceof pattern flow scoping (GA J16); switch pattern GA J21.
  • Switch trên String desugar 2 tầng (hashCode + equals).
  • NIO: buffer + channel + selector (1 thread N connection); tránh Java serialization (RCE).

1 Records internals

record Point(int x, int y) {}
Compiler sinh gì

Field private final mỗi component, canonical constructor, accessor (x() không phải getX()), equals/hashCode/toString qua invokedynamic + ObjectMethods.bootstrap (nhất quán mọi component), class final kế thừa java.lang.Record.

record Range(int lo, int hi) {
    Range {   // compact constructor: validate, chạy trước gán field ẩn
        if (lo > hi) throw new IllegalArgumentException();
    }
}
Immutable KHÔNG sâu

Field final nhưng nếu component là kiểu mutable (List, mảng) thì nội dung vẫn đổi được qua reference. Muốn bất biến sâu phải defensive copy trong compact constructor + accessor.

2 Sealed classes

sealed interface Shape permits Circle, Square, Rectangle {}
record Circle(double r) implements Shape {}
Enforce ở đâu

Compile-time (chỉ class trong permits được implement) VÀ runtime (class file attribute PermittedSubclasses). Subtype phải là final, sealed, hoặc non-sealed.

Sealed + record = ADT

Algebraic data type: sum type (Shape = Circle | Square | Rectangle qua sealed) + product type (record). Cho phép switch pattern matching exhaustive không cần default, thay visitor pattern cồng kềnh.

3 Pattern matching

// instanceof pattern (GA J16): check + bind + guard, bỏ cast
if (obj instanceof String s && s.length() > 3) { use(s); }

// switch pattern matching (preview J17, GA J21):
switch (shape) {
    case Circle c    -> ...;
    case Square s    -> ...;
    // sealed -> exhaustive, không cần default
}
Ghi chú

instanceof pattern bind biến chỉ trong scope điều kiện chắc đúng (flow scoping), bỏ cast thủ công. J21 thêm record deconstruction case Circle(double r) và guard case Integer i when i > 0. Tài liệu này dùng if-instanceof cho JDK 17.

4 Switch expression & desugaring

int days = switch (month) {
    case JAN, MAR, MAY -> 31;      // arrow: không fall-through
    case FEB -> 28;
    default -> { int d = compute(month); yield d; }  // yield trả giá trị
};
  • Expression trả giá trị; arrow không fall-through (không cần break); yield cho block.
  • Exhaustiveness với enum/sealed → compiler yêu cầu đủ nhánh (quên = lỗi compile).
Desugaring

Switch trên int/enum → tableswitch (dày) hoặc lookupswitch (thưa). Switch trên String → 2 tầng: hashCode() nhóm case rồi equals() xác nhận (tránh hash collision). Switch pattern matching → invokedynamic (SwitchBootstraps).

5 Text blocks

String json = """
    {
      "name": "an"
    }""";   // Java 15+

Bỏ escape \n, \". Compiler xử lý incidental whitespace (thụt lề chung, xác định bởi vị trí """ đóng). \ cuối dòng = nối dòng; \s = giữ space cuối. Chỉ là syntactic sugar → kết quả là String thường.

6 var — local type inference

Không phải dynamic typing

var chỉ suy kiểu lúc compile từ vế phải, kiểu vẫn tĩnh & cố định, không overhead runtime. Chỉ dùng cho biến local có khởi tạo; không field, tham số, return type, hay null. Nên dùng khi kiểu hiển nhiên (var list = new ArrayList<String>()).

Vì sao buffered

Đọc từng byte trực tiếp = 1 syscall/byte → rất chậm. BufferedInputStream đọc một khối vào bộ nhớ rồi phục vụ từng byte từ buffer → giảm số syscall hàng nghìn lần.

8 NIO

3 khái niệm cốt lõi
  • Buffer (ByteBuffer): position/limit/capacity; flip() chuyển ghi→đọc; direct buffer off-heap.
  • Channel (FileChannel, SocketChannel): hai chiều, làm việc với buffer, có thể non-blocking.
  • Selector: 1 thread select() giám sát nhiều channel → xử lý channel sẵn sàng.

9 Serialization

Nên tránh Java Serialization
  • Bảo mật: deserialize dữ liệu không tin cậy → RCE (gadget chain, readObject chạy code).
  • Gắn chặt: serialVersionUID + cấu trúc class → khó đổi version.
  • Không cross-language, nhị phân khó debug.
Thay bằng

JSON (Jackson/Gson) cho API; Protobuf/Avro cho hiệu năng + schema evolution. Nếu buộc dùng: đặt ObjectInputFilter (J9+) whitelist/blacklist class, giới hạn depth.

10 Follow-up questions

Interviewer hay đào tiếp
  • Record sinh equals/hashCode thế nào? → invokedynamic + ObjectMethods.bootstrap.
  • Record immutable sâu không? → không nếu component mutable; cần defensive copy.
  • Sealed enforce ở đâu? → compile + class file attribute PermittedSubclasses.
  • instanceof pattern lợi gì? → check + bind + flow scoping, bỏ cast.
  • Switch trên String desugar thế nào? → hashCode nhóm + equals xác nhận (2 tầng).
  • var có làm chậm runtime không? → không, chỉ suy kiểu compile-time.
  • Selector cho phép làm gì? → 1 thread giám sát nhiều channel (Netty).
  • Direct buffer là gì? → off-heap, giảm copy khi I/O, cấp phát đắt hơn.
  • Vì sao tránh Java serialization? → RCE khi deserialize không tin cậy.

? Flashcards

QRecord được compiler sinh ra những gì?+

Field private final cho mỗi component, canonical constructor, accessor tên component (x() không phải getX()), equals/hashCode/toString (qua invokedynamic + ObjectMethods.bootstrap), class final kế thừa java.lang.Record. Không extends class khác.

QRecord có immutable sâu không?+

Không hẳn. Field là final nhưng nếu component là kiểu mutable (List, mảng) thì nội dung vẫn thay đổi được qua reference. Muốn bất biến sâu phải defensive copy trong compact constructor và accessor.

QCompact constructor chạy khi nào?+

Chạy trước phần gán field ẩn. Không khai báo tham số/không gán this.field; gán vào tham số để normalize thì compiler tự copy vào field. Dùng để validate hoặc chuẩn hoá.

QSealed class enforce ở đâu?+

Compile-time (chỉ class trong permits được implement) VÀ runtime (ghi vào class file attribute PermittedSubclasses). Subtype phải là final, sealed, hoặc non-sealed.

QSealed + record cho phép mô hình gì?+

Algebraic data type: sum type (Shape = Circle | Square | Rectangle qua sealed) + product type (record). Cho phép switch pattern matching exhaustive không cần default, thay visitor pattern.

Qinstanceof pattern matching lợi gì?+

if (o instanceof String s) vừa check kiểu vừa bind biến s đã cast (flow scoping: s chỉ dùng được khi chắc đúng kiểu). Bỏ cast thủ công dễ sai. GA từ Java 16.

QSwitch expression khác switch statement?+

Expression trả giá trị; arrow -> không fall-through (không cần break); yield trả giá trị từ block; exhaustive với enum/sealed (thiếu nhánh = lỗi compile). An toàn hơn switch cũ.

Qswitch trên String desugar thế nào?+

2 tầng: dùng hashCode() để nhóm các case (tableswitch/lookupswitch trên hash), rồi equals() xác nhận đúng chuỗi (tránh hash collision). Switch trên int/enum dùng tableswitch/lookupswitch trực tiếp.

QText block xử lý thụt lề thế nào?+

Compiler loại "incidental whitespace" (thụt lề chung, xác định bởi vị trí """ đóng). \ cuối dòng nối dòng, \s giữ space cuối. Chỉ là syntactic sugar, kết quả là String thường.

Qvar có phải dynamic typing không?+

Không. var là local type inference: compiler suy kiểu từ vế phải, kiểu vẫn tĩnh và cố định, không overhead runtime. Chỉ cho biến local có khởi tạo, không field/tham số/return/null.

Qjava.io dùng design pattern nào?+

Decorator: bọc stream để thêm khả năng, vd new DataInputStream(new BufferedInputStream(new FileInputStream(f))). InputStreamReader là cầu byte→char kèm charset (nên chỉ định UTF-8).

QVì sao buffered stream nhanh hơn nhiều?+

Đọc từng byte trực tiếp = 1 syscall/byte, rất chậm. BufferedInputStream đọc một khối vào bộ nhớ rồi phục vụ từng byte từ buffer → giảm số syscall hàng nghìn lần.

Q3 khái niệm cốt lõi của NIO?+

Buffer (vùng nhớ có position/limit/capacity, flip() chuyển ghi↔đọc, có direct buffer off-heap), Channel (hai chiều, làm việc với buffer, có thể non-blocking), Selector (1 thread select() giám sát nhiều channel).

QNIO khác IO blocking thế nào về mô hình thread?+

IO cũ: 1 thread/1 connection (blocking) → nhiều kết nối tốn nhiều thread. NIO với selector: 1 thread giám sát N channel, chỉ xử lý channel sẵn sàng → 1 thread phục vụ hàng nghìn kết nối (nền của Netty).

QDirect buffer là gì, đánh đổi?+

ByteBuffer off-heap (allocateDirect): giảm copy giữa JVM heap và OS khi I/O → nhanh cho I/O lớn. Đánh đổi: cấp phát/thu hồi đắt hơn, không do GC thường quản (dễ leak nếu giữ lâu).

QVì sao tránh Java Serialization?+

Deserialize dữ liệu không tin cậy có thể RCE (gadget chain, readObject chạy code); gắn chặt cấu trúc class (serialVersionUID, khó đổi version); không cross-language; nhị phân khó debug. Thay bằng JSON hoặc Protobuf/Avro.

QNếu buộc dùng Java serialization thì phòng thủ thế nào?+

Dùng ObjectInputFilter (Java 9+) để whitelist/blacklist class được deserialize, giới hạn depth/số object, chặn các gadget class nguy hiểm. Không bao giờ deserialize dữ liệu từ nguồn không tin cậy mà không lọc.

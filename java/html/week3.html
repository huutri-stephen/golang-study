Functional Programming & Streams

Lambda KHÔNG phải anonymous class (invokedynamic + LambdaMetafactory); Stream pipeline chạy bằng Spliterator + Sink; ForkJoinPool chung ảnh hưởng khi parallel.

i Overview & TL;DR

TL;DR
  • Lambda = invokedynamic + LambdaMetafactory, không sinh class con lúc compile.
  • Stateless lambda được reuse (theo call site); capturing lambda tạo instance mới.
  • Stream: Spliterator + Sink, xử lý chiều dọc, không collection trung gian.
  • Lazy + short-circuit (findFirst/limit); stateful op (sorted/distinct/limit) là rào cản.
  • Collector 4 phần; toMap trùng key cần merge function.
  • parallelStream chạy ForkJoinPool.commonPool → tránh trong web request.

1 Lambda: invokedynamic

Sai lầm phổ biến

"Lambda là đường tắt của anonymous inner class" — KHÔNG đúng.

Anonymous class

Sinh class file riêng (Outer$1.class) lúc compile, new Outer$1() lúc runtime.

Lambda

Compiler tạo invokedynamic call site + method lambda$main$0. Lần đầu chạy, bootstrap LambdaMetafactory.metafactory sinh lớp implement rồi cache.

Vì sao thiết kế vậy

Không nổ số class file (mỗi lambda 1 class như anonymous → tăng load + metaspace). JVM tự do chọn chiến lược tạo instance: lambda không capture được reuse cùng instance (theo call site); có capture thì tạo mới giữ biến (closure).

2 Capture & effectively final

int base = 10;                          // effectively final
Function<Integer,Integer> f = x -> x + base;   // capture base bằng giá trị
// base = 20; -> LỖI COMPILE: must be effectively final
  • Lambda capture biến local bằng giá trị (copy vào field ẩn). Local trên stack có thể biến mất trước lambda → phải copy.
  • Cấm gán lại để tránh nhập nhằng giá trị giữa lambda và code ngoài.
  • Capture this/field → capture reference → lambda giữ object bao ngoài (có thể leak nếu sống lâu).

5 Stream pipeline internals

3 thành phần
  • Source → tạo Spliterator (tryAdvance duyệt, trySplit chia đôi cho parallel).
  • Intermediate ops → xâu chuỗi các Sink (lazy, chưa chạy).
  • Terminal op → đẩy từng phần tử qua chuỗi Sink.
Xử lý theo chiều dọc (không collection trung gian)
phần tử
filter
map
collect
Mỗi phần tử đi dọc qua toàn bộ chuỗi Sink MỘT lần, không phải filter tất cả rồi map tất cả → tiết kiệm bộ nhớ + cho phép short-circuit.
Stateful vs stateless

Stateless (map/filter/peek) xử lý độc lập. Stateful (sorted/distinct/limit) cần buffer/nhìn nhiều phần tử → tạo rào cản (barrier), giảm hiệu quả parallel. sorted phải gom hết mới sort.

6 Lazy evaluation & short-circuit

Stream.of("a", "bb", "ccc", "dddd")
    .filter(s -> { print("filter " + s); return s.length() > 1; })
    .map(s -> { print("map " + s); return s.toUpperCase(); })
    .findFirst();
// filter a, filter bb, map bb  -> DỪNG (không đụng ccc, dddd)

Không có terminal op → không chạy gì. Short-circuit: findFirst, findAny, anyMatch, allMatch, limit → dừng sớm nhờ lazy.

7 Collectors sâu

// groupingBy + downstream
Map<String,Long> c = users.stream()
    .collect(groupingBy(User::city, counting()));
// toMap + merge (tránh IllegalStateException khi trùng key)
.collect(toMap(User::name, User::age, (a, b) -> a));
Collector là gì bên dưới (4 phần)

supplier (tạo container), accumulator (thêm phần tử), combiner (gộp 2 container khi parallel — phải associative), finisher (biến đổi cuối). Hiểu điều này giúp viết custom collector.

Bẫy toMap trùng key

toMap không merge function → IllegalStateException khi 2 phần tử cùng key. Luôn cung cấp merge function nếu key có thể trùng.

8 Optional đúng cách

Đúng

  • opt.map(...).orElse(default)
  • opt.ifPresentOrElse(...)
  • opt.orElseThrow(...)

Sai

  • opt.get() không check → NoSuchElementException
  • Optional làm field/tham số (không Serializable)
  • Optional<List> (trả list rỗng)

Optional là kiểu trả về biểu diễn "có thể không có", không phải công cụ chống null khắp nơi.

9 Parallel stream & ForkJoinPool

Chạy trên đâu

parallelStream() dùng ForkJoinPool.commonPool() — chung toàn JVM (size = cores-1). Chia việc bằng trySplit (fork/join + work-stealing), gộp bằng combiner.

Hiệu quả khi

  • Data lớn + thao tác nặng, độc lập
  • Nguồn dễ chia (ArrayList/array)
  • Không shared mutable state

KHÔNG nên khi

  • Trong web request (chiếm common pool)
  • Data nhỏ / thao tác nhẹ (overhead > lợi ích)
  • Nguồn khó chia (LinkedList/IO)
// Nếu bắt buộc parallel: dùng ForkJoinPool riêng
ForkJoinPool pool = new ForkJoinPool(4);
pool.submit(() -> list.parallelStream()...).get();

10 Follow-up questions

Interviewer hay đào tiếp
  • Lambda có phải anonymous class? → Không; invokedynamic + LambdaMetafactory.
  • Lambda tạo object mới mỗi lần? → không capture reuse; có capture tạo mới.
  • Vì sao capture phải effectively final? → capture bằng copy giá trị.
  • Stream có collection trung gian giữa op không? → không, đi dọc qua chuỗi Sink.
  • Stateful op nào gây rào cản? → sorted, distinct, limit.
  • 4 thành phần Collector? → supplier, accumulator, combiner, finisher.
  • toMap trùng key nổ gì? → IllegalStateException; cung cấp merge function.
  • parallelStream chạy pool nào? → ForkJoinPool.commonPool; tránh web request.
  • Vì sao IntStream tốt hơn Stream<Integer>? → không boxing, có sum/average.

? Flashcards

QLambda có phải đường tắt của anonymous inner class không?+

Không. Anonymous class sinh class file riêng (Outer$1.class). Lambda dùng invokedynamic + bootstrap LambdaMetafactory.metafactory sinh lớp implement lúc runtime lần đầu rồi cache. Không sinh class con lúc compile, tránh nổ số class file.

QLambda có tạo object mới mỗi lần đánh giá không?+

Lambda KHÔNG capture (stateless): JVM thường tái dùng cùng 1 instance (theo call site). Lambda có capture: tạo instance mới giữ biến bắt được (như closure). Stateless lambda gần như miễn phí.

QVì sao lambda capture phải effectively final?+

Lambda capture biến local bằng cách copy giá trị (local trên stack có thể biến mất trước khi lambda chạy). Cấm gán lại để tránh nhập nhằng giá trị giữa lambda và code ngoài.

QLambda trong instance method capture gì? Rủi ro?+

Capture reference tới this (object bao ngoài) khi dùng field/method của nó. Nếu lambda sống lâu (đăng ký listener) có thể giữ object bao ngoài không cho GC → memory leak.

QVì sao có biến thể IntFunction, ToIntFunction, IntStream?+

Tránh autoboxing Integer trong hot path. Stream<Integer> box/unbox mỗi phần tử tốn RAM và GC; IntStream lưu int nguyên thuỷ, có sum/average sẵn. mapToInt để chuyển.

Q4 loại method reference?+

static (Integer::parseInt), instance của object cụ thể (out::println), instance của kiểu tham số (String::toUpperCase), constructor (ArrayList::new).

QStream chạy thế nào bên dưới?+

Source tạo Spliterator (tryAdvance duyệt, trySplit chia đôi). Intermediate op xâu chuỗi các Sink (lazy). Terminal op đẩy từng phần tử qua chuỗi Sink. Không tạo collection trung gian giữa các op.

Qfilter().map().collect() có tạo list sau mỗi op không?+

Không. Mỗi phần tử đi DỌC qua toàn bộ chuỗi Sink một lần (filter→map→collect), không phải filter tất cả rồi map tất cả. Nhờ đó tiết kiệm bộ nhớ và cho phép short-circuit.

QStateful vs stateless intermediate op?+

Stateless (map/filter/peek) xử lý độc lập từng phần tử. Stateful (sorted/distinct/limit) cần buffer/nhìn nhiều phần tử, tạo rào cản trong pipeline, giảm hiệu quả (đặc biệt parallel). sorted phải gom hết mới sort.

QLazy evaluation nghĩa là gì trong Stream?+

Intermediate op không chạy tới khi có terminal op. Kết hợp xử lý theo chiều dọc + short-circuit (findFirst/limit/anyMatch) cho phép dừng sớm, bỏ qua phần tử thừa.

QCollector gồm những phần nào?+

supplier (tạo container), accumulator (thêm phần tử), combiner (gộp 2 container khi parallel), finisher (biến đổi cuối). Combiner phải associative để parallel đúng.

QtoMap trùng key gây gì? Cách xử lý?+

IllegalStateException (duplicate key). Cung cấp merge function: toMap(k, v, (a,b)->a) để chọn giá trị khi trùng, hoặc (a,b)->b, hoặc gộp.

QgroupingBy trả gì, lồng được không?+

Map<K, List<T>> mặc định. Downstream: groupingBy(city, counting()) → Map<String,Long>. Lồng nhiều tầng: groupingBy(city, groupingBy(isAdult)) → Map<String, Map<Boolean, List>>.

QOptional dùng sai như thế nào?+

get() không check (NoSuchElementException), Optional làm field/tham số (không Serializable, sai ý định), Optional<List> (nên trả list rỗng), if(isPresent())get() thay map/orElse. Optional chỉ nên là kiểu trả về "có thể không có".

QparallelStream chạy trên pool nào? Rủi ro?+

ForkJoinPool.commonPool() chung toàn JVM (size = cores-1). Trong web request, parallel stream chiếm common pool → chặn request khác → giảm throughput toàn app. Nếu cần, dùng ForkJoinPool riêng qua submit().get().

QKhi nào KHÔNG nên parallel stream?+

Data nhỏ / thao tác nhẹ (overhead chia+gộp > lợi ích), có shared mutable state/side effect, nguồn khó chia (LinkedList/IO), hoặc trong web request. Chỉ hiệu quả với data lớn + thao tác nặng độc lập + nguồn dễ chia.

QforEach vs forEachOrdered trên parallel stream?+

forEach không đảm bảo thứ tự (chạy song song). forEachOrdered giữ thứ tự gặp (encounter order) nhưng mất phần lớn lợi ích song song. Muốn kết quả có thứ tự thường dùng collect thay forEach.

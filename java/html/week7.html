4 Mockito internals

Cách tạo mock

Dùng ByteBuddy (trước CGLIB) sinh subclass runtime của class được mock, override method để trả stub/ghi tương tác. Vì thế không mock được final class/method (không override được) trừ khi bật mockito-inline.

@ExtendWith(MockitoExtension.class)
class UserServiceTest {
    @Mock UserRepo repo;                // mock rỗng
    @InjectMocks UserService service;   // inject @Mock vào (ctor→setter→field)
    @Test void t() {
        when(repo.findById(1L)).thenReturn(user);  // stub
        verify(repo, times(1)).findById(1L);        // verify
    }
}

@Spy bọc object thật, chỉ stub method chỉ định (còn lại chạy thật). Test pyramid: nhiều unit > ít integration > rất ít e2e.

5 JDBC & HikariCP

Vì sao connection pool

Tạo connection DB tốn kém: TCP + TLS + auth + session DB (ms–chục ms). Pool giữ sẵn connection mở, tái sử dụng → giảm latency đột biến. HikariCP nhanh nhờ ConcurrentBag lock-free.

Pool lớn KHÔNG luôn tốt hơn

Nhiều connection hơn số DB xử lý được → context switch + lock contention ở DB → chậm hơn. Pool nhỏ (10-20) thường tốt hơn. Tham khảo PostgreSQL: connections ≈ core*2 + spindle. Đo thực nghiệm. maxLifetime tái tạo connection cũ tránh bị DB/LB đóng ngầm.

6 Hibernate: persistence context

Persistence context = L1 cache

EntityManager/Session quản lý persistence context: bộ nhớ đệm entity managed trong 1 transaction. Query cùng entity 2 lần → lần 2 lấy từ context (không query lại). L1 cache luôn bật, phạm vi transaction.

@Transactional void changeEmail(long id, String email) {
    User u = em.find(User.class, id);   // managed
    u.setEmail(email);                    // chỉ set field
    // KHÔNG cần save() -> flush lúc commit tự sinh UPDATE

Hibernate chụp snapshot entity managed lúc load; lúc flush so state hiện tại với snapshot → tự sinh UPDATE cho field đổi.

flush vs commit; L1 vs L2

flush: đồng bộ xuống DB (chạy SQL) nhưng chưa commit (tự động trước query + lúc commit). commit: flush + kết thúc transaction. L1 per-transaction luôn bật; L2 (@Cacheable + Ehcache/Caffeine) chia sẻ giữa session, phải cấu hình.

8 Transaction & isolation

Bẫy @Transactional
  • Self-invocation: gọi method @Transactional trong cùng class → không qua proxy → vô hiệu.
  • Method private/non-public → proxy không chặn → vô hiệu.
  • Checked exception mà quên rollbackFor → commit dù có lỗi.
  • Nuốt exception bên trong → transaction không thấy lỗi → không rollback.
Propagation

REQUIRED (mặc định): join hoặc tạo mới. REQUIRES_NEW: suspend cái cũ, tạo transaction mới độc lập (audit log commit dù transaction ngoài rollback). NESTED: savepoint. Isolation: READ_COMMITTED (mặc định), REPEATABLE_READ, SERIALIZABLE.

9 Logging & JSON

SLF4J facade

SLF4J là API trừu tượng; binding runtime: Logback (mặc định Spring Boot) hoặc Log4j2. Log parameterized: log.info("user {} did {}", uid, action) — chỉ nối chuỗi khi level bật. Không log.debug("..." + heavy()).

Jackson: không serialize entity trực tiếp

ObjectMapper thread-safe (tái dùng singleton). Bẫy: circular reference (2 entity trỏ nhau) → StackOverflow; lazy proxy → lỗi/tải dư. Map sang DTO, hoặc @JsonIgnore/@JsonManagedReference.

? Flashcards

QMaven resolve version conflict thế nào?+

Nearest-wins: chọn version ở độ sâu nhỏ nhất trong cây dependency; cùng độ sâu thì khai báo trước thắng. Ép version bằng dependencyManagement hoặc import BOM. Khác Gradle (highest-version wins).

QDependency scope của Maven?+

compile (mọi nơi, mặc định), provided (compile+test, không đóng gói - servlet API), runtime (không cần compile - JDBC driver), test (chỉ test - JUnit/Mockito). Scope quyết định classpath ở từng giai đoạn.

QGradle nhanh hơn Maven nhờ gì?+

Task-based DAG chỉ chạy task cần thiết; incremental build (input không đổi → UP-TO-DATE, bỏ qua); build cache tái dùng output giữa máy/CI; daemon. Đổi lại script phức tạp hơn XML khai báo của Maven.

QJUnit 5 gồm mấy phần?+

Platform (nền chạy test, launcher), Jupiter (API viết test mới + extension), Vintage (chạy test JUnit 3/4 cũ).

QJUnit 5 tạo bao nhiêu instance test?+

Mặc định PER_METHOD: mỗi test method một instance mới → cô lập trạng thái. @TestInstance(PER_CLASS) dùng một instance cho cả class (cho phép @BeforeAll non-static).

QExtension model của JUnit 5 thay gì của JUnit 4?+

Thay Runner + Rule bằng Extension interface (BeforeEachCallback, ParameterResolver...). @ExtendWith(MockitoExtension.class) cắm Mockito, @ExtendWith(SpringExtension.class) cho Spring Test. assertAll gom nhiều assert báo tất cả lỗi.

QMockito tạo mock bằng cách nào?+

Dùng ByteBuddy (trước CGLIB) sinh subclass runtime của class được mock, override method để trả stub/ghi tương tác. Vì thế không mock được final class/method (không override được) trừ khi dùng mockito-inline.

Q@Mock vs @InjectMocks vs @Spy?+

@Mock tạo mock rỗng. @InjectMocks tạo instance thật của class test và tự inject các @Mock (constructor→setter→field). @Spy bọc object thật, chỉ stub method chỉ định, còn lại chạy thật.

QVì sao không mock được final method?+

Mockito tạo subclass và override; final method không override được. Cần mockito-inline (bytecode instrumentation) hoặc thiết kế test qua interface. Static/private cũng cần mockito-inline (mockStatic).

QVì sao luôn dùng connection pool?+

Tạo connection DB tốn kém (TCP + TLS + auth + session DB, hàng ms). Pool giữ sẵn connection mở tái sử dụng → giảm latency. HikariCP nhanh nhờ ConcurrentBag lock-free.

QPool lớn có luôn tốt hơn không?+

Không. Nhiều connection hơn số DB xử lý được → context switch + lock contention ở DB → chậm hơn. Pool nhỏ (10-20) thường tốt hơn. Tham khảo: connections ≈ core*2 + spindle. Đo thực nghiệm.

QmaxLifetime của pool để làm gì?+

Tái tạo connection sau một khoảng thời gian, tránh dùng connection cũ đã bị DB/load balancer đóng ngầm (gây "connection reset"). Nên đặt nhỏ hơn timeout của DB/LB.

QPersistence context là gì?+

Bộ nhớ đệm entity managed trong một transaction (L1 cache, luôn bật). Query cùng entity 2 lần trong 1 transaction → lần 2 lấy từ context, không query DB lại. EntityManager/Session quản lý nó.

QDirty checking hoạt động thế nào?+

Hibernate chụp snapshot entity managed lúc load. Lúc flush/commit, so sánh state hiện tại với snapshot, tự sinh UPDATE cho field đã đổi. Nên chỉ cần setField() trong transaction, KHÔNG cần gọi save().

QVì sao set field entity ngoài transaction không update DB?+

Ngoài transaction entity ở trạng thái detached, không được persistence context theo dõi → không dirty checking → không sinh UPDATE. Phải merge lại vào một transaction.

Qflush vs commit?+

flush đồng bộ persistence context xuống DB (chạy SQL) nhưng chưa commit transaction; xảy ra tự động trước query và lúc commit. commit = flush + kết thúc transaction (DB commit thật).

QL1 vs L2 cache?+

L1 = persistence context, per-transaction, luôn bật. L2 = second-level cache (@Cacheable + Ehcache/Caffeine), chia sẻ giữa các session/transaction, phải cấu hình, cẩn thận invalidation.

QN+1 problem và cách fix?+

1 query lấy N entity + N query lazy lấy association từng cái = 1+N query. Fix: JOIN FETCH (JPQL), @EntityGraph (khai báo đồ thị fetch), @BatchSize (gom thành query IN). Không dùng EAGER bừa.

QFetch type mặc định của các association?+

@ManyToOne và @OneToOne mặc định EAGER. @OneToMany và @ManyToMany (collection) mặc định LAZY. LAZY trả proxy; truy cập sau khi session đóng → LazyInitializationException.

QLazyInitializationException xảy ra khi nào?+

Truy cập một lazy association sau khi persistence context (session/transaction) đã đóng → proxy không thể load. Fix: fetch trong transaction (JOIN FETCH/@EntityGraph) hoặc map sang DTO trong transaction.

QBẫy @Transactional self-invocation?+

Gọi method @Transactional từ method khác TRONG CÙNG class → không qua proxy Spring → annotation không có tác dụng (không mở transaction). Lỗi phổ biến nhất với Spring AOP. Tách sang bean khác hoặc self-inject.

QPropagation REQUIRED vs REQUIRES_NEW?+

REQUIRED (mặc định): join transaction hiện có hoặc tạo mới. REQUIRES_NEW: luôn tạo transaction mới, suspend cái đang chạy (dùng cho audit log cần commit độc lập dù transaction ngoài rollback).

QVì sao không serialize entity Hibernate ra JSON trực tiếp?+

Lazy association là proxy → serialize gây LazyInitializationException hoặc tải dư; circular reference (2 entity trỏ nhau) gây StackOverflow. Nên map sang DTO. Dùng @JsonIgnore/@JsonManagedReference nếu buộc.

QVì sao log parameterized log.info("x={}", x) tốt hơn nối chuỗi?+

Chỉ format/nối chuỗi khi log level được bật. log.debug("..." + heavy()) luôn tính heavy() dù debug tắt. Parameterized tránh chi phí thừa và an toàn hơn.

TL;DR
  • Erasure: generics chỉ ở compile; compiler chèn checkcast ở nơi get → CCE nổ khi lấy ra.
  • Bridge method: nối chữ ký generic sau erasure để giữ đa hình.

1 Generics & type erasure sâu

Erasure làm gì

Generics chỉ tồn tại lúc compile để type-check, sau đó xoá: List<String> → List; T không bound → Object; T extends Number → Number. Compiler chèn cast tự động ở nơi lấy phần tử ra.

List<String> l = new ArrayList<>();
String s = l.get(0);   // bytecode: invokeinterface get -> checkcast String

checkcast chèn ở điểm get ⇒ heap pollution (raw type nhét sai kiểu) nổ ClassCastException tại điểm lấy ra, không phải nhét vào.

2 Bridge method

class Node<T> { void set(T value) {...} }
class StringNode extends Node<String> {
    @Override void set(String value) {...}   // muốn override set(T)
}
Vì sao cần bridge

Sau erasure Node.set có chữ ký set(Object), còn StringNode.set(String) khác tham số → không phải override. Compiler sinh bridge method synthetic: set(Object o) { set((String) o); } để nối invokevirtual set(Object) về set(String), giữ đa hình. Thấy được qua javap — giải thích method "lạ" với tham số Object trong stack trace/reflection.

3 PECS & variance

Generics invariant

List<String> KHÔNG phải List<Object> (khác mảng covariant). Wildcards cho variance có kiểm soát.

// PRODUCER extends: chỉ đọc ra
double sum(List<? extends Number> src) {
    for (Number n : src) ...   // src.add(x) KHÔNG compile
}
// CONSUMER super: chỉ ghi vào
void addInts(List<? super Integer> dst) {
    dst.add(1);   // đọc ra chỉ được Object
}

Ví dụ chuẩn: Collections.copy(List<? super T> dest, List<? extends T> src).

4 Reifiable & mảng generic

Reifiable là gì

Type mà runtime giữ đầy đủ thông tin (primitive, non-generic class, List<?>, Object). Generic parameterized type KHÔNG reifiable. Mảng covariant + reifiable → xung đột với generics.

Object[] arr = new String[3];
arr[0] = 42;   // compile OK, RUNTIME ArrayStoreException

// List<String>[] a = new List<String>[3];  // LỖI COMPILE
List<String>[] a = (List<String>[]) new List[3];  // unchecked, dễ heap pollution

Ưu tiên List<List<String>> thay vì mảng của generic.

Hàm spread hash
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

Index = (n-1) & hash. Vì n lũy thừa 2, (n-1) chỉ giữ bit thấp → hashCode khác ở bit cao thì cùng bucket. h ^ (h>>>16) trộn bit cao xuống thấp → phân phối đều, chi phí 1 XOR.

Vì sao capacity lũy thừa 2

Dùng (n-1) & hash thay % n — bit AND nhanh hơn chia. Chỉ đúng khi n lũy thừa 2 (mask liên tục bit thấp).

Treeify & resize (ngưỡng chính xác)
  • Treeify khi bucket ≥ 8 (TREEIFY_THRESHOLD) VÀ table ≥ 64 (MIN_TREEIFY_CAPACITY). Table < 64 → resize trước. Untreeify khi ≤ 6.
  • Ngưỡng 8 vì Poisson với hash tốt: xác suất bucket 8 phần tử ~6e-8 → treeify chỉ là van an toàn chống hash xấu/tấn công.
  • Resize J8: capacity gấp đôi; mỗi phần tử ở index cũ hoặc index cũ + oldCap (bit hash & oldCap) → tách lo/hi, không rehash toàn bộ.
  • Load factor 0.75: thấp hơn → ít collision tốn RAM; cao hơn → tiết kiệm RAM nhiều collision.
Liên hệ equals/hashCode

get(key): tính hash → chọn bucket → duyệt tìm node hash bằng && (key==k || key.equals(k)). Sai contract → tìm sai bucket/so sai → mất entry.

7 ConcurrentHashMap

Java 7

Chia 16 Segment, mỗi segment là HashTable con có lock riêng → concurrency level = số segment.

Java 8

Bỏ segment. Bucket rỗng thêm bằng CAS (lock-free); bucket có node thì synchronized trên node đầu bucket đó. size dùng CounterCell (LongAdder-style).

Vì sao cấm null

get(k)==null mơ hồ giữa "không có key" và "value null". Đa luồng không dùng containsKey phân biệt an toàn (race) → cấm cả null key lẫn value.

8 Iterator: fail-fast vs fail-safe

Fail-fast (ArrayList, HashMap)

Dựa modCount. Sửa cấu trúc khi duyệt (không qua iterator) → ConcurrentModificationException ở lần next() kế (best-effort).

// SAI
for (String s : list) if (s.isEmpty()) list.remove(s);  // CME
// ĐÚNG
list.removeIf(String::isEmpty);   // hoặc iterator.remove()
Fail-safe

CopyOnWriteArrayList: ghi copy cả mảng, iterator duyệt snapshot cũ → không CME nhưng không thấy thay đổi mới, ghi O(n) → chỉ hợp đọc nhiều ghi rất ít. ConcurrentHashMap iterator: weakly consistent, không ném CME.

? Flashcards

QType erasure làm gì với T và T extends Number?+

T không bound → erase về Object; T extends Number → erase về Number (bound đầu tiên). Compiler chèn checkcast ở nơi lấy phần tử ra. Runtime không còn thông tin generic.

QVì sao ClassCastException do heap pollution nổ ở điểm lấy ra?+

Compiler chèn checkcast tại điểm get chứ không phải add. Dùng raw type nhét sai kiểu qua được compile, tới khi get + cast mới nổ CCE.

QBridge method là gì?+

Method synthetic compiler sinh khi override generic method. Sau erasure Node.set(T)→set(Object) nhưng StringNode.set(String) khác chữ ký; compiler sinh bridge set(Object){set((String)o);} để giữ đa hình.

QLàm sao vượt giới hạn new T() do erasure?+

Truyền Class<T> rồi clazz.getDeclaredConstructor().newInstance(), hoặc truyền Supplier<T>. Runtime không biết T nên cần thông tin type từ bên ngoài.

QGenerics của Java invariant nghĩa là gì?+

List<String> KHÔNG phải List<Object> (không gán được), khác mảng covariant. Muốn variance dùng wildcard: ? extends (covariant, đọc), ? super (contravariant, ghi).

QVì sao mảng generic bị cấm?+

Mảng reifiable + covariant (nhớ type runtime, ném ArrayStoreException). Generic non-reifiable (erasure). Kết hợp phá type safety không phát hiện được runtime → compiler cấm new List<String>[n].

QPECS đầy đủ?+

Producer Extends Consumer Super. ? extends T: đọc ra T, chỉ ghi null. ? super T: ghi T, đọc ra Object. Vừa đọc vừa ghi: T cụ thể. VD Collections.copy(List<? super T> dest, List<? extends T> src).

QArrayList grow bao nhiêu mỗi lần?+

newCap = oldCap + (oldCap >> 1) = 1.5x. Default cap 10 (lazy). Copy bằng Arrays.copyOf O(n) nhưng amortized O(1)/add. Biết size trước thì new ArrayList<>(size).

Qadd(index)/remove(index) của ArrayList phức tạp bao nhiêu?+

O(n) vì System.arraycopy dịch các phần tử sau vị trí. get/set O(1). add cuối amortized O(1). ArrayList vẫn thắng LinkedList nhờ cache locality.

QIndex bucket HashMap tính thế nào?+

(n-1) & hash(key) với n là capacity (lũy thừa 2). Dùng bit AND thay % vì nhanh hơn; chỉ đúng khi n lũy thừa 2.

QVì sao HashMap dùng h ^ (h >>> 16)?+

Index chỉ dùng bit thấp (n-1)&hash. Nếu hashCode khác nhau chỉ ở bit cao thì cùng bucket → collision. XOR dịch 16 trộn bit cao xuống thấp để phân phối đều, chi phí 1 XOR.

QTreeify khi nào? Vì sao ngưỡng 8?+

Bucket ≥8 phần tử VÀ table ≥64 → cây đỏ-đen (O(log k)). Table<64 thì resize trước. Ngưỡng 8 vì Poisson với hash tốt: xác suất bucket 8 phần tử ~6e-8 → van chống hash xấu/tấn công.

QResize Java 8 tối ưu rehash thế nào?+

Capacity gấp đôi. Mỗi phần tử ở index cũ hoặc index cũ + oldCap, quyết định bằng 1 bit hash & oldCap. Tách list thành 2 (lo/hi) mà không tính lại hash toàn bộ.

QLoad factor 0.75 đánh đổi gì?+

size > cap*0.75 thì resize. Thấp hơn → ít collision nhưng tốn RAM, resize sớm. Cao hơn → tiết kiệm RAM nhưng nhiều collision, tra cứu chậm. 0.75 cân bằng thời gian/không gian.

QConcurrentHashMap Java 8 khoá gì (khác Java 7)?+

Java 7 chia 16 Segment mỗi cái có lock. Java 8 bỏ segment: bucket rỗng thêm bằng CAS (lock-free); bucket có node thì synchronized trên node đầu bucket → chỉ khoá 1 bucket, các bucket khác song song.

QVì sao ConcurrentHashMap cấm null?+

get(k)==null mơ hồ giữa "không có key" và "value null". Đa luồng không thể dùng containsKey phân biệt an toàn (race). Nên cấm cả null key và null value.

QConcurrentHashMap đếm size thế nào để tránh contention?+

Dùng mảng CounterCell (kiểu LongAdder): mỗi thread cộng vào cell riêng, size = baseCount + tổng các cell. Tránh mọi thread tranh một biến counter chung.

QFail-fast dựa vào gì? Có đảm bảo không?+

Dựa modCount. Iterator lưu expectedModCount, mỗi next() so sánh, khác thì ném ConcurrentModificationException. Best-effort, KHÔNG đảm bảo phát hiện mọi trường hợp.

QXóa phần tử khi duyệt sao cho đúng?+

Dùng Iterator.remove() (cập nhật cả modCount và expectedModCount), hoặc list.removeIf(predicate), hoặc duyệt bản copy. Không dùng for-each rồi collection.remove() (gây CME).

QCopyOnWriteArrayList phù hợp khi nào?+

Đọc nhiều, ghi cực ít (listener list, config). Ghi copy toàn mảng O(n); đọc lock-free trên snapshot. Iterator không ném CME nhưng không thấy thay đổi sau khi tạo.

QArrayList vs LinkedList?+

ArrayList mảng động: get O(1), cache locality tốt. LinkedList: thêm/xóa đầu-cuối O(1) nhưng get(i) O(n), tốn bộ nhớ node. Thực tế gần như luôn dùng ArrayList.
